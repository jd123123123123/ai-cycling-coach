<objective>
Replace vague "4 option" coach brief with a ONE precisely-prescribed workout grounded in the athlete's actual FTP, CTL, TSB, recent load, and a named training framework. Then redesign the dashboard hierarchy iPhone-style: ONE headline surface (today's prescribed workout) dominates the fold; everything else stacks below with progressive disclosure.

**User bar (verbatim):** "really precise recommendations and not high level… the app should be like an iphone. You open it, you know where to find what and everything you see brings immense value and cognitive deload"

Precision means: power targets per interval block in absolute watts (computed from FTP), duration per block in minutes, total TSS predicted, expected EF range post-ride, framework cited by name (e.g. "Friel Build 2 · VO2 micro"). Not "push today".

iPhone hierarchy means:
1. **Fold 1 (above the fold):** Prescribed workout + verdict + 1-line rationale. Nothing else.
2. **Fold 2:** KPI strip (HRV/body battery/sleep/TSB) — raw numbers, one row.
3. **Fold 3:** PMC chart at full width.
4. **Fold 4:** Collapsed sections (Biometrics Detail, Recent Activities, Calendar) — tap to expand.

Every surface that exists must answer "what do I do with this information?" If it doesn't, it gets cut or moved below fold 4.
</objective>

**Science frameworks to encode (pick per-day based on block position + freshness):**
- **Coggan zones** (Z1–Z7) by %FTP: Z1 <55, Z2 56-75, Z3 76-90, Z4 91-105, Z5 106-120, Z6 121-150, Z7 >150
- **Seiler polarized 80/20**: weekly ratio Z1-Z2 vs above-LT. Use `zone_distribution` snapshot
- **Friel periodization** — base/build/peak/taper; pick phase from days-to-goal + CTL trajectory
- **San Millán Z2 ceiling** — long Z2 endurance builds mitochondrial density; HR drift ≤6bpm at fixed power is the adaptation signal
- **Mujika taper** — 40–60% volume cut, maintain intensity, 7–14 days before goal
- **Banister fitness-fatigue** — already computed via PMC; use TSB to gate intensity
- **Skiba W'bal** (if power streams available later) — not required for first cut

**Workout templates (v1 — precise but small set; AI can compose from these):**
- `recovery_30` — 30min Z1 (55% FTP), TSS ≈ 15
- `z2_endurance_60` — 60min at 65% FTP ±5% (Z2), TSS ≈ 45
- `z2_endurance_90` — 90min at 65% FTP ±5%, TSS ≈ 68
- `z2_long_120` — 2h at 65% FTP, TSS ≈ 90
- `z2_long_180` — 3h at 65% FTP, TSS ≈ 135 (San Millán signature)
- `sweet_spot_2x20` — 15 warmup + 2×20min at 88% FTP, 5min rec, 10 cooldown. TSS ≈ 85
- `threshold_2x15` — 15 warmup + 2×15min at 100% FTP, 6min rec, 10 cooldown. TSS ≈ 78
- `vo2_5x4` — 15 warmup + 5×4min at 115% FTP, 3min rec, 10 cooldown. TSS ≈ 72
- `vo2_micro_30x30` — 15 warmup + 30×30s at 120% FTP / 30s at 50% FTP, 10 cooldown. TSS ≈ 65
- `tempo_3x10` — 15 warmup + 3×10min at 85% FTP, 3min rec, 10 cooldown. TSS ≈ 70
- `rest_day` — no workout; the prescription itself
- `over_under_3x5` — 15 warmup + 3×(1min 105% / 1min 95%)×5 sets, 5min rec, 10 cooldown. TSS ≈ 78

Each template is parametric — duration and power% scale with phase (base → build → peak).

**Selector logic (v1 rules-based BEFORE LLM):**
1. `safety_rails.intensity_ceiling` gives the max intensity allowed
2. Goal phase (base/build/peak/taper) from days-to-goal + goal type
3. Weekly state (how much volume + intensity already logged this week vs weekly target)
4. Session position (is today meant to be intensity, volume, or recovery in the polarized plan)
5. Pick a template, parametrize with current FTP
6. LLM sees the picked template + can tune duration ±15% / substitute to adjacent template if context demands

The LLM does NOT invent intervals from scratch — it selects and tunes. This prevents hallucinated workouts.

```python
@dataclass(frozen=True)
class IntervalBlock:
    name: str                    # "Warm-up", "Main 1", "Recovery", "Cool-down"
    duration_s: int
    target_pct_ftp: float        # 0.65 = 65% FTP
    target_rpe: int              # 1-10 optional
    zone: int                    # Coggan 1-7

@dataclass(frozen=True)
class WorkoutTemplate:
    id: str                      # "vo2_5x4"
    name: str                    # human display
    category: Literal['recovery','endurance','tempo','sweet_spot','threshold','vo2','anaerobic']
    purpose: str                 # "Builds VO2 ceiling"
    framework_cited: str         # "Coggan Z5 · Friel Build"
    blocks: list[IntervalBlock]
    base_tss: float              # approximate TSS at the template's designed volume
    min_ftp_required: int | None # skip if athlete FTP < this (safety)

TEMPLATES: dict[str, WorkoutTemplate] = {...}

def parametrize_template(template: WorkoutTemplate, ftp: int, duration_scale: float = 1.0) -> PrescribedWorkout:
    """Returns concrete watts-per-block. duration_scale stretches long intervals but NOT warmup/cooldown.
       Output PrescribedWorkout has absolute watts, absolute minutes, predicted TSS.
    """

@dataclass
class PrescribedWorkout:
    template_id: str
    title: str                   # "VO2 — 5×4min"
    framework_cited: str         # "Coggan Z5 · Friel Build 2"
    purpose: str
    total_duration_s: int
    predicted_tss: float
    predicted_ef_range: tuple[float, float]  # NP/HR expected post-workout
    blocks: list[ResolvedBlock]  # each has absolute_watts, duration_s, zone, rpe

@dataclass(frozen=True)
class ResolvedBlock:
    name: str
    duration_s: int
    target_watts_low: int        # ±5% band
    target_watts_high: int
    target_pct_ftp: float
    zone: int
    rpe: int
```
