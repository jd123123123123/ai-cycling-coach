  <name>Task 1: Create confidence.ts pure utility</name>
  <files>frontend/src/utils/confidence.ts</files>
  <action>
    Create `frontend/src/utils/confidence.ts` exporting a pure `confidence(input: ConfidenceInput): ConfidenceLevel` function and the `ConfidenceLevel` / `ConfidenceInput` types.

    SHAPE:
    ```ts
    export type ConfidenceLevel = 'high' | 'low'

    export interface ConfidenceInput {
      // Number of days of relevant data the metric is computed from
      n_days?: number | null
      // Minimum days required for 'high' confidence (e.g. 7 for HRV, 14 for CTL trend, 7 for polarized)
      min_days: number
      // Optional preconditions — any false flag forces 'low' (e.g. has_ftp=false → no PMC trend)
      preconditions?: Record<string, boolean | null | undefined>
    }

    export function confidence(input: ConfidenceInput): ConfidenceLevel {
      const days = input.n_days ?? 0
      if (days < input.min_days) return 'low'
      if (input.preconditions) {
        for (const v of Object.values(input.preconditions)) {
          if (v === false || v == null) return 'low'
        }
      }
      return 'high'
    }
    ```

    Also export named constants for the standard thresholds (so consumers don't magic-number them):
    ```ts
    export const MIN_DAYS_HRV = 7
    export const MIN_DAYS_CTL_TREND = 14
    export const MIN_DAYS_POLARIZED = 7
    ```

    Use `// U+2212` typographic minus convention if the file references signed numbers (it shouldn't here — keep it pure).

    NO React imports. NO async. NO date-fns. Pure function over plain objects.

    Why this shape (record in a top-of-file comment):
    - Single function call replaces 11 places where consumers would otherwise inline `if (n_days >= 7) ...`
    - Preconditions object is optional so polarized (only n_days) and CTL trend (n_days + has_ftp) share the same signature
    - Returns 'high' | 'low' (binary), not a 0..1 score — UI only ever needs to switch between "show the number" and "show the placeholder," and we don't want to invent a third state in v1
  </action>
