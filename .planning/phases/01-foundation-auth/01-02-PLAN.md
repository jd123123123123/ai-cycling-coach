  <action>
    1. Create Alembic migration for new tables + RLS:
       `cd backend && alembic revision --autogenerate -m "add profiles consent and RLS"`

    2. In the migration, AFTER the autogenerated table creation, add op.execute() calls for RLS:
       ```sql
       -- Enable RLS on all user-data tables
       ALTER TABLE athlete_profiles ENABLE ROW LEVEL SECURITY;
       ALTER TABLE consent_records ENABLE ROW LEVEL SECURITY;

       -- Create isolation policies
       -- current_setting with 'true' second arg returns NULL instead of error when not set
       CREATE POLICY user_isolation ON athlete_profiles
           USING (user_id = current_setting('app.current_user_id', true)::INTEGER);
       CREATE POLICY user_isolation ON consent_records
           USING (user_id = current_setting('app.current_user_id', true)::INTEGER);

       -- Also create future-proof tables for Phase 3 as hypertables
       -- activities table (hypertable)
       CREATE TABLE IF NOT EXISTS activities (
           id BIGSERIAL,
           user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
           started_at TIMESTAMPTZ NOT NULL,
           sport VARCHAR(30) NOT NULL,
           duration_seconds INTEGER,
           distance_meters FLOAT,
           tss FLOAT,
           normalized_power FLOAT,
           average_power FLOAT,
           average_hr INTEGER,
           max_hr INTEGER,
           calories INTEGER,
           title VARCHAR(200),
           source VARCHAR(50),
           external_id VARCHAR(100),
           raw_data JSONB,
           created_at TIMESTAMPTZ DEFAULT NOW(),
           PRIMARY KEY (id, started_at)
       );
       SELECT create_hypertable('activities', 'started_at', chunk_time_interval => INTERVAL '7 days', if_not_exists => TRUE);
       ALTER TABLE activities ENABLE ROW LEVEL SECURITY;
       CREATE POLICY user_isolation ON activities
           USING (user_id = current_setting('app.current_user_id', true)::INTEGER);

       -- daily_metrics table (hypertable)
       CREATE TABLE IF NOT EXISTS daily_metrics (
           id BIGSERIAL,
           user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
           date DATE NOT NULL,
           recorded_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
           sleep_score INTEGER,
           hrv_status FLOAT,
           body_battery INTEGER,
           resting_hr INTEGER,
           stress_level INTEGER,
           steps INTEGER,
           weight_kg FLOAT,
           source VARCHAR(50),
           raw_data JSONB,
           PRIMARY KEY (id, recorded_at),
           UNIQUE (user_id, date)
       );
       SELECT create_hypertable('daily_metrics', 'recorded_at', chunk_time_interval => INTERVAL '30 days', if_not_exists => TRUE);
       ALTER TABLE daily_metrics ENABLE ROW LEVEL SECURITY;
       CREATE POLICY user_isolation ON daily_metrics
           USING (user_id = current_setting('app.current_user_id', true)::INTEGER);
       ```

    3. Add downgrade to remove RLS and drop tables in reverse order.

    4. Update `backend/app/dependencies.py` to add `get_db_for_user`:
       ```python
       async def get_db_for_user(
           current_user: User = Depends(get_current_user),
           db: AsyncSession = Depends(get_db),
       ) -> AsyncGenerator[AsyncSession, None]:
           await db.execute(text(f"SET LOCAL app.current_user_id = '{current_user.id}'"))
           yield db
       ```
       NOTE: Keep `get_db` (without user context) available for registration and other unauthenticated routes. Use `get_db_for_user` for all user-data routes.

    5. Update athletes.py, goals.py, consent.py to use `get_db_for_user` instead of `get_db` for their database sessions. This enables RLS as defense-in-depth on top of the application-level user_id filtering.

    6. Run migration: `cd backend && alembic upgrade head`

    7. Verify RLS works by testing cross-user isolation:
       - Register user A, create profile
       - Register user B, create profile
       - User A cannot see user B's profile (and vice versa)
       - Direct SQL with wrong user_id returns empty results
