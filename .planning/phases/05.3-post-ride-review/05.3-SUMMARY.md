# Phase 05.3 Plan 01: Post-Ride Review + Goal Trajectory Summary

**One-liner:** When the athlete has already trained today, the fold-1 hero swaps from "today's workout" to a graded post-ride review — 5-grade compliance scoring (Coggan), EF/VI/decoupling read (San Millán / Friel), CTL/TSB projection to race day (Banister / Mujika), and a specific next-session nudge — in both technical and simple language modes, with a full deterministic rule-based fallback that needs no API key.

## Shape

1. **Scoring is deterministic and pure.** `score_ride(Activity, WorkoutTemplate, ftp, phase, session_type) → RideCompliance` grades duration + TSS against the template the periodization layer would have picked. Five grades (perfect / strong / okay / overcooked / undercooked) with explicit first-match rules. Phase-aware: offseason/maintenance grade against absolute TSS bands instead of template target.

2. **Trajectory projection is deterministic and pure.** `project(pmc_list, goals, phase) → TrajectoryProjection` linear-extrapolates CTL from the trailing 7-day delta, layers Mujika's taper ATL-decay model on top during the final 14 days, and classifies race-day form (too_flat / ideal / too_fresh / overreached). Every narrative emits a plain-English hook suitable for the card's trajectory slot — even when no goal is set ("Consistency is the goal — your fitness is trending +0.8/week").

3. **Both paths produce the review.** The rule-based synthesiser (`_build_post_ride_review`) branches on (grade, session_type, language) and emits the full `{headline, physiological_read, goal_trajectory, next_session_nudge}`. The LLM path merges its narrative fields over the deterministic builder — compliance numbers are never LLM-writable (the scorer is the authority). This means the app ships without an API key and still gets a complete mindblowingly-good review.

4. **The review lives inside `evidence` JSONB.** No schema migration. `CoachBrief.evidence` already holds the snapshot; we drop `post_ride_review` in alongside `language`. `_brief_to_read` extracts and validates via Pydantic on response, tolerating pre-5.3 rows (key missing → None).

5. **Frontend renders it as the fold-1 hero.** `PostRideReview.tsx` replaces `PrescribedWorkoutCard` when `brief.post_ride_review != null`. Grade pill (colour-coded), Fraunces italic headline, compliance trio (Duration · Effort · EF), three paragraphs (physio / trajectory / nudge), staggered motion mount (0 → 0.6s). Perfect gets pulse/glow; overcooked gets a small warning micro-copy; okay/strong/undercooked stay quiet (cognitive deload).

6. **Simple-mode is airtight.** Backend rule-based synthesiser and frontend labels both scrub jargon; the test suite asserts no FTP/TSS/CTL/TSB/NP/IF/VI/EF/Coggan/Seiler/Friel/Banister/San Millán/Mujika/polarized/decoupling appears in any simple-mode review narrative across all five grades. Technical-mode tests assert at least one framework name appears.

## Open Follow-ups (not blocking)

- **Stream-based zone-distribution compliance.** `ride_compliance.zone_match_pct` is reserved but unused — activating it requires per-second power streams, which Phase 3's Garmin sync doesn't persist yet. When streams land, `score_ride` can compute actual zone-time vs template-intended zone distribution.
- **Decoupling from raw_data.** Currently `ride_compliance` looks for `raw_data.decoupling_pct` if the mapper pre-computed it. `advanced_metrics.compute_activity_metrics` has the streams-based path; we haven't wired the result back into `activity.raw_data`. Small follow-up: persist decoupling during garmin_mapper so post-ride review can cite San Millán drift on long Z2 rides.
- **Kolie Moore RPE decoupling.** Noted in the plan as a future hook. Requires user-reported RPE, which the app doesn't yet collect.
- **Yesterday-morning retrospective review.** The plan mentions retrospectively showing the post-ride review next morning. The current implementation is today-only (`today_tss >= 25`). A lightweight follow-up: if today's tss is zero AND yesterday's tss >= 25 AND no post_ride_review exists for the current calendar day, generate one for yesterday's session. Not implemented in this plan to keep scope tight.
