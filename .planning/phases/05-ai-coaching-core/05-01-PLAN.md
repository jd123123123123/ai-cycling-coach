<objective>
Ship the backend for the "Frontier Coach" — a causal, transparent AI training brief grounded in the best sports-science frameworks and filtered by hard safety rails. Every brief cites the athlete's own data. No black-box scores.

Closes underserved gaps from `.planning/research/athlete-pain-points.md`:
- #1 "Why am I tired?" synthesizer (Section 4 pain point #1)
- #2 Causal recommendations with explainability (addresses TrainerRoad/Runna complaints)
- #3 Tier-1 metrics nobody surfaces: aerobic decoupling trend, EF trend, durability index
- #4 HRV/rHR overlaid on training load (Altini's critique — raw data, no composites)
- #5 Zone-distribution + grey-zone-creep detection (Seiler framework)
- #6 Safety rails hard-coded (addresses AI-app overtraining injuries)
</objective>

<downstream_consumer>
Frontend plan 05-02 consumes these endpoints:
- `POST /coach/brief` → `{verdict, rationale, evidence, options[4], outlook_7d, frameworks_cited}`
- `POST /coach/brief/refresh` → force-regenerate (cache-bust)
- `POST /coach/chat` → SSE stream `text/event-stream`
- `GET /coach/why` → raw snapshot + system prompt for transparency toggle
</downstream_consumer>

<task id="2" name="advanced-metrics-service">
**Goal:** Pure functions that compute the Tier-1 metrics the research flagged as commercially absent. Backend-only; frontend has its own `advanced-metrics.ts` that stays as-is.

Create `backend/app/services/advanced_metrics.py`:

```python
# All functions are pure. Input = primitive data; output = float/dict. No DB access.

def aerobic_decoupling(first_half_np: float, first_half_hr: float,
                       second_half_np: float, second_half_hr: float) -> float:
    """Pw:HR drift. <5% = excellent aerobic base.
       Formula: ((second/first_second) - (first/first_first)) / first_pw_hr.
       Per TrainingPeaks definition.
    """

def efficiency_factor(normalized_power: float, avg_hr: float) -> float:
    """NP / avgHR. Higher = aerobic fitness improving."""

def durability_index(fresh_np: float, fatigued_np: float) -> float:
    """Late-ride / fresh power ratio (0..1). Per 2025 PMC study."""

def compute_activity_metrics(activity) -> dict:
    """Extract decoupling, EF, durability from a single activity.
       Requires activity.power_samples or activity.hr_samples (may be None).
       Returns {decoupling: float|None, ef: float|None, durability: float|None}.
    """

# DB-backed helpers (accept AsyncSession, user_id, days):

async def hrv_trend(db, user_id: int, days: int = 7) -> dict:
    """Returns {current_mean, baseline_28d_mean, delta_pct, samples_n, direction}.
       Pulls from daily_metrics.hrv_status."""

async def rhr_trend(db, user_id: int, days: int = 7) -> dict:
    """Same shape as hrv_trend but for resting_hr (lower = better)."""

async def sleep_debt(db, user_id: int, days: int = 14) -> dict:
    """Cumulative sleep shortfall vs 8h target (in hours).
       Returns {total_debt_hours, avg_nightly_debt, nights_short, nights_healthy}."""

async def zone_distribution(db, user_id: int, days: int = 28) -> dict:
    """Polarized 3-zone % across N days of cycling activities.
       Returns {z1_pct, z2_pct, z3_pct, total_hours, grey_zone_flag: bool}.
       grey_zone_flag = True when z2 > 20% (Seiler's creep threshold).
    """

async def ctl_atl_tsb_snapshot(db, user_id: int) -> dict:
    """Wraps pmc_service for coach consumption. Returns last 7 days trend.
       {ctl, atl, tsb, ctl_7d_delta, tsb_7d_delta, form_status}.
       form_status: 'fresh'|'optimal'|'grey'|'risk' by TSB thresholds (+25/+5/-10/-30).
    """

async def why_am_i_tired(db, user_id: int) -> dict:
    """Synthesizer — cross-references all of the above.
       Returns ordered list of suspected causes with evidence.
       {causes: [{label, severity: 'low'|'med'|'high', evidence: str}, ...]}
    """
```

- Missing/null power or HR samples → return None for that metric
- Fewer than 7 days of daily_metrics → return `samples_n` field so caller can downgrade confidence
- Timezone-agnostic date windows (use `date.today()` local)

<task id="3" name="safety-rails-service">
**Goal:** Hard-coded guardrails that filter AI recommendations. These run AFTER the LLM returns — the LLM can suggest anything; rails strip dangerous options before response.

Create `backend/app/services/safety_rails.py`:

```python
@dataclass
class RailContext:
    ctl: float
    atl: float
    tsb: float
    hrv_delta_pct: float  # 7d vs 28d baseline
    injury_flag: bool
    days_since_rest: int

def max_tss_for_day(ctl: float) -> float:
    """TSS ceiling = 1.3 × CTL. Rationale: >1.5×CTL = overload territory."""

def intensity_ceiling(ctx: RailContext) -> str:
    """Returns 'rest'|'easy'|'moderate'|'push' — max intensity allowed today.
       Rules (first match wins):
       - injury_flag → 'rest'
       - hrv_delta_pct < -10 → 'easy'
       - tsb < -30 → 'easy'
       - tsb < -10 → 'moderate'
       - days_since_rest >= 10 → 'moderate' (forced recovery)
       - default → 'push'
    """

def filter_recommendation(options: list[dict], ctx: RailContext) -> list[dict]:
    """Input: 4 options from LLM. Output: same list with disallowed options
       marked {blocked: True, reason: str}. Never silently drops an option —
       transparency requires showing what was filtered and why.
    """

ED_KEYWORDS = ['restrict calories', 'skip meals', 'drop weight fast',
               'intermittent fasting before training', 'low body fat goal', ...]

def scan_nutrition_advice(text: str) -> list[str]:
    """Returns list of ED-adjacent phrases found. Empty = safe.
       Used to veto chat responses before streaming to user."""

def validate_chat_response(text: str) -> tuple[bool, str]:
    """Returns (allowed, replacement_text_if_blocked).
       If ED phrases detected → blocked with canned safe redirect message."""
```

Add tests for every branch. Commit: `feat(05-01): safety rails with TSS caps intensity ceilings ED filter`
</task>

**System prompt skeleton** (store in `backend/app/services/coach_prompt.py`):

```
You are an elite endurance coach trained in:
- Seiler's polarized 80/20 framework (intensity distribution matters more than volume)
- Banister fitness-fatigue (CTL/ATL/TSB, TSB < -30 = overreach risk)
- San Millán Zone 2 (HR drift at fixed power = Z2 ceiling adaptation signal)
- Friel periodization (base → build → peak → recovery cycles)
- Kolie Moore (RPE-vs-power decoupling catches overreach before biomarkers)

RULES YOU MUST FOLLOW:
1. Cite the athlete's OWN data in every recommendation. Never give generic advice.
2. Explain WHY. Never just prescribe without reasoning.
3. Offer 4 options: rest / easy / moderate / push. Each with a "why this" rationale.
4. Never recommend training through injury. Never suggest intermittent fasting or
   caloric restriction. Never mention weight loss as a training goal.
5. If HRV is suppressed >10% or TSB < -30 or athlete has injury_flag=True, default
   your verdict to caution and explain exactly which signal drove the decision.
6. Reference 2-3 of the frameworks above by name in your rationale.

You will receive the athlete's full snapshot and return STRUCTURED OUTPUT via the
brief_response tool.
```

**Tool schema** forces shape:
```json
{
  "name": "brief_response",

            "tss_target": {"type": "number"}

        "type": "array", "minItems": 7, "maxItems": 7,
```
