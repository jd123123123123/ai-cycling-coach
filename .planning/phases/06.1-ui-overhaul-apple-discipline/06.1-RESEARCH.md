## What this phase must answer

**Core question:** Should I train today, and how hard? (Above-the-fold discipline — WHOOP's thesis, Apple Fitness' thesis. Every UI decision is measured against this.)

**Design-direction choice (settled):** **Path B — editorial voice + Apple structural discipline.**

- **Keep:** amber/forest/paper palette, serif hero numerals, masthead ("The Coach · Daily · est. 2026"), colophon, dateline, editorial typography (existing `num-display`, `eyebrow` classes).
- **Adopt from Apple HIG:** segmented dashboard tabs, bento grid, side sheets, sticky summary bar, Cmd+K command palette, spring-physics motion tokens, unified "why this?" (contributors) drawer, explicit sync-status pill.
- **Do not:** replace system palette with iOS blues/greens, swap the serif numerals for SF Pro, add confetti/badges/streaks (those belong in Phase 9 with psychology guardrails).

### Design-token pass (Tailwind config)

Add to `tailwind.config.js` under `theme.extend`:
- `borderRadius`: `xs:6 sm:10 md:14 lg:20 xl:28 2xl:36 pill:9999`
- `boxShadow`: `shadow-1..4` + `glass-rim` (see apple-2027 §1.5)
- `backdropBlur`: `10 20 30 40 50` → ultra-thin → ultra-thick materials
- `transitionTimingFunction`: `apple-default`, `apple-decel`, `apple-accel`
- Spring token map in a helper (JS, not Tailwind): `{ smooth, snappy, interactive, gentle, bouncy }` → Framer Motion `{ stiffness, damping }` conversion
- Apple Intelligence gradient utility class for AI surfaces (chat input when composing, coach ambient state)

**Palette stays editorial.** Do not replace `--color-*` variables.

## Known risks / pitfalls

1. **Editorial + Apple tension.** Liquid Glass materials on an editorial amber surface can look muddy. Glass should sit over a *content canvas with color* (apple-2027 §1.6). The editorial `--color-paper` (warm cream) is fine; avoid applying glass over solid amber.
2. **Motion regression.** Existing `motion/react` animations (post-05-02) must keep working; adding spring tokens shouldn't break the existing `layoutId` / `AnimatePresence` call sites in `CoachChat`, `WorkoutModifiedCard`, `CoachBrief`.
3. **Bundle size.** Current frontend gzipped is ~534 KB (per STATE.md). `cmdk` adds ~4 KB. Any chart-motion decoration must not bloat. Enforce ≤10% growth overall as an implicit budget.
4. **`TransparencyDrawer` migration.** The 06-03 "Tools Used" live-subscription pattern (via module-singleton `chatToolUseLog.ts`) must port cleanly into `ContributorsSheet`. Don't break the live-update invariant.
5. **Route isolation.** The plan must not introduce new routes that break deep links. `/dashboard` stays the single entry; segmented tabs are client-side state (search param OK).
6. **Language toggle propagation.** New primitives must respect the existing `lang` preference from `LanguageToggle`. Side sheets, command palette, dynamic pill all render simple-mode copy by default.
7. **Test coverage.** No current Playwright / Cypress E2E suite — visual verification is manual. Unit tests exist via Vitest for some components. Accept this; success criteria #5 (Cmd+K) and #1 (above-the-fold) deserve at least `@testing-library/react` assertions.

## Plan-breakdown guidance (suggested shape)

Three sequential waves — each roughly 1 week of work, safe to ship independently:

1. **Wave 1 — Tokens + Primitives (foundation):**
   - Design-token pass in `tailwind.config.js` (radii, shadows, blur, easing)
   - Motion preset helper (`src/utils/motion.ts` — already exists, extend it)
   - Build `SideSheet`, `SegmentedTabs`, `BentoGrid` with stories/tests
   - No dashboard restructure yet — primitives only. Ship green.

2. **Wave 2 — Dashboard restructure (apply primitives):**
   - Introduce `Today / Week / Trends / Plan` segmented tabs in `DashboardPage` (URL param)
   - Move components into their tab homes per REDESIGN-BRIEF §3
   - Replace all in-page "detail" modals with `SideSheet`
   - Add `StickyReadinessBar`
   - Add `IconRail` + route structure for Calendar / Activities / Coach / Settings pages (can reuse existing dashboard for now; new pages are shells + placeholders — acceptable)
   - Above-the-fold audit at 1440×900

3. **Wave 3 — Polish + power features:**
   - `CommandPalette` (Cmd+K)
   - Unified `ContributorsSheet` merging `TransparencyDrawer` + `WhyAmITired`
   - Explicit sync-status pill (per-provider timestamps)
   - Apple Intelligence gradient on `CoachChat` input during streaming
   - Chart Apple-polish pass (gradient fill, no gridlines, draw-on) — bounded scope: PMC + Polarized + Intensity
   - Defer to Phase 06.2 (optional): `DynamicPill`, View Transitions API, weekly recap

Each wave's PLAN.md should have: frontmatter (wave, depends_on, files_modified, autonomous), task list in XML, verification criteria, must_haves derived from the phase success criteria.
