Ship the backend for **COACH-05 workout modification via chat**: a new `modify_planned_workout` tool that lets the LLM intent-express user requests ("I only have 45 min", "make it harder", "swap to indoor") and have the backend execute the modification through the existing template library + safety_rails, never bypassing either.

Purpose: users want to express modifications in natural language. Without this tool, chat is read-only. WITH this tool, the LLM can read user intent, emit a structured modification, and the backend authoritatively applies it — preserving the 05.1 decision that "Templates are the atomic unit. LLM picks/substitutes; server rewrites all watts."

Output: A pure modifier service, a new tool registered with the LLM, a rails-gated execution path, audit persistence on coach_briefs, and comprehensive tests covering every modification type × every rails-violation scenario.

**Explicitly not in scope:** chat UI rendering the modification (→ 06-03), undo affordance (→ 06-04 or folded into 06-03), multi-turn context passing (→ 06-04).

**Architectural decisions (non-negotiable):**
- [05.1-01]: Templates atomic. LLM picks/substitutes from 12-template library, cannot author intervals from scratch. Server rewrites all watts.
- [05.1-01]: Rails enforcement via template downgrade when only ONE workout per day — substitute via `_safe_template_for_ceiling(ceiling)`, noted inline in why_this_workout
- [05-01]: coach_briefs append-only audit; 6h TTL is read-through cache on latest row
- [05-01]: Rails applied AFTER LLM — mark blocked=True with reason (never silently drop)
- [05.1-01]: Invalid LLM template_id falls back to snapshot.picked_template_id
- Server-side authority for safety-critical numbers

**The 12-template library (from 05.1):** z1_recovery_30, z2_endurance_60, z2_endurance_90, tempo_2x20, sweet_spot_2x15, sweet_spot_2x20, sweet_spot_3x15, threshold_2x20, vo2_5x4, vo2_6x3, anaerobic_8x1, rest_day — ordered roughly by intensity/TSS. The harder/easier cascades traverse this list.

**Safety rails in scope (from 05-01):** `intensity_ceiling` (blocks above-ceiling templates per recovery state), `tss_cap_relative_to_ctl` (blocks TSS > 1.5×CTL single-day), `injury_flag` (forces rest_day or z1_recovery_30 only). **New rail in this plan (from 06-RESEARCH):** `already_trained_today` — if `date == today` and a completed Activity exists for the user on that date (or `post_ride` evidence present on latest coach_brief), REJECT the modification with `{success: False, reason: 'Already trained today — nothing to modify.'}`. Mirrors `resolve_and_prescribe` behavior.

**Note on duration bending:** LLM was already allowed to bend `duration ±15%` in 05.1 (clamped twice). The `shorten`/`lengthen` modifications extend this — bending `>15%` triggers template substitution (e.g., z2_endurance_90 → z2_endurance_60 for 'shorten' that lands below the 15% floor).

```python
from dataclasses import dataclass
from app.services.safety_rails import apply_rails  # existing
from app.services.template_library import TEMPLATE_LIBRARY, parametrize_template

# Ordered by TSS. Index-based cascade.
ORDERED_TEMPLATES = [
    "rest_day", "z1_recovery_30",
    "z2_endurance_60", "z2_endurance_90",
    "tempo_2x20",
    "sweet_spot_2x15", "sweet_spot_2x20", "sweet_spot_3x15",
    "threshold_2x20",
    "vo2_6x3", "vo2_5x4",
    "anaerobic_8x1",
]

TEMPLATE_HARDER_CASCADE = {t: ORDERED_TEMPLATES[min(i+1, len(ORDERED_TEMPLATES)-1)]
                           for i, t in enumerate(ORDERED_TEMPLATES)}
TEMPLATE_EASIER_CASCADE = {t: ORDERED_TEMPLATES[max(i-1, 0)]
                           for i, t in enumerate(ORDERED_TEMPLATES)}

@dataclass
class ModificationResult:
    template_id: str
    duration_min: int
    blocks: list
    indoor: bool
    rails_downgraded: bool
    reason: str
    before: dict

def apply_modification(planned_workout, modification_type, params, user_snapshot, ftp_w):
    before = {"template_id": planned_workout.template_id,
              "duration_min": planned_workout.duration_min}

    # 1. Injury override — strongest rail
    if user_snapshot.get("injury_flag"):
        return ModificationResult(
            template_id="z1_recovery_30",
            duration_min=30,
            blocks=parametrize_template("z1_recovery_30", ftp_w)["blocks"],
            indoor=params.get("indoor", False),
            rails_downgraded=True,
            reason="injury flag active; easy recovery only",
            before=before,
        )

    # 2. Dispatch by modification_type
    if modification_type == "shorten":
        return _apply_shorten(planned_workout, params, ftp_w, before)
    elif modification_type == "lengthen":
        return _apply_lengthen(planned_workout, params, ftp_w, before)
    elif modification_type == "harder":
        return _apply_harder(planned_workout, user_snapshot, ftp_w, before)
    elif modification_type == "easier":
        return _apply_easier(planned_workout, ftp_w, before)
    elif modification_type == "indoor":
        return _apply_indoor(planned_workout, ftp_w, before)
    else:
        raise ValueError(f"Unknown modification_type: {modification_type}. "
                         f"Allowed: shorten, lengthen, harder, easier, indoor")

def _apply_harder(pw, snapshot, ftp_w, before):
    current = pw.template_id
    next_template = TEMPLATE_HARDER_CASCADE[current]
    ceiling = snapshot.get("intensity_ceiling", "vo2")  # default permissive

    # Check if next_template respects ceiling
    if _template_exceeds_ceiling(next_template, ceiling):
        next_template = _safe_template_for_ceiling(ceiling)  # reuse from 05.1
        rails_downgraded = True
        reason = f"blocked by intensity ceiling ({ceiling}) due to recovery state"
    else:
        rails_downgraded = False
        reason = "substituted up one step in harder cascade"

    materialized = parametrize_template(next_template, ftp_w, duration_override=pw.duration_min)
    return ModificationResult(
        template_id=next_template,
        duration_min=materialized["duration_min"],
        blocks=materialized["blocks"],
        indoor=pw.indoor,
        rails_downgraded=rails_downgraded,
        reason=reason,
        before=before,
    )
# ... _apply_shorten, _apply_lengthen, _apply_easier, _apply_indoor similar
```

```python
async def _handle_modify_planned_workout(tool_input, user_id, db):
    date = tool_input["date"]
    pw = await _get_planned_workout(user_id, date, db)
    if pw is None:
        return {"found": False, "reason": f"No planned workout on {date}"}

    # New rail: already-trained-today guard (from 06-RESEARCH Pitfall 3 extension)
    if date == today_iso() and await _has_activity_on(user_id, date, db):

    # Load user snapshot (readiness, ceiling, injury_flag, tss_cap)
    snapshot = await _build_user_snapshot(user_id, db)
    profile = await _get_athlete_profile(user_id, db)

    result = apply_modification(
        pw, tool_input["modification_type"], tool_input.get("params", {}),

    pw.template_id = result.template_id
    pw.duration_min = result.duration_min

    pw.blocks_source = "user_modified"

        "duration_min": result.duration_min,
```
