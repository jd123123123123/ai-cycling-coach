## Accomplishments

- **Language toggle end-to-end:** Backend splits coach_prompt into simple (default, plain English, no FTP/TSS/CTL/Z-numbers) vs technical (current rich vocabulary, each jargon term followed by ≤5-word parenthetical). Frontend LanguageToggle in the masthead persists per-browser in localStorage; toggling switches every coach surface without a page reload.
- **Language-aware rule-based fallback:** When ANTHROPIC_API_KEY is missing the coach still works — and still respects language mode. A friend-at-the-bike-shop phrase map drives simple-mode verdicts ("You're good to go"), rationales ("Your body's tired from what you've been doing"), titles ("Easy spin"), alternates ("Got 30 min? Just spin the legs"), outlook notes, and frameworks cited.
- **Language-keyed backend cache:** get_or_generate_brief filters `evidence->>'language' == language` (Pydantic-coalesced 'simple' for pre-5.2 rows). Different language = cache miss = regenerate; same language = cache hit.
- **Frontend cache-key discipline:** useCoachBrief's React Query key is `['coach','brief',language]` so toggling mutates the key and triggers an automatic refetch. useRefreshBrief regenerates for the active language only.
- **Sync button:** 36×28 RefreshCw icon button with three states (idle / syncing-spinning / done-green-pulse for 1.2s). On success invalidates daily-metrics, activities, pmc, coach-brief, intraday, and garmin-status — the dashboard re-renders with fresh data without a reload. 6-second auto-dismissing inline error toast extracts the server's detail field for 404 (no account) / 409 (already syncing) / 401 (auth) / 500 (generic).
- **Full coach-surface audit:** CoachBrief, PrescribedWorkoutCard, IntervalRibbon, WhyAmITired, KpiStripCompact, TransparencyDrawer, CoachChat all read the current language and switch phrasing. TransparencyDrawer stays technical (by design — it's the "show me the raw data" view) but adds a friendly intro line for simple-mode users.
- **Coverage:** 15 new backend tests under test_language_modes.py enforce (a) simple-mode rationale/title/why/alternates/outlook/frameworks contain none of the banned jargon substrings, (b) technical-mode still uses FTP/TSS/CTL/TSB/Banister/Friel/Seiler, (c) missing or invalid `language` defaults to 'simple', (d) different language triggers cache miss + regenerate, same language hits cache.

## Decisions Made

- **Default language is simple.** Non-athlete users should not have to discover the toggle; athletes who want the dense view can opt into technical. This is why `= 'simple'` is the default on every schema + endpoint.
- **`SYSTEM_PROMPT` stays as a backward-compat alias for the technical prompt.** `/coach/transparency` and any ancillary importers continue working without a rename churn; new call sites use `system_prompt_for_language()`.
- **Cache key lives in JSONB, not a column.** Storing `language` inside `evidence` means zero migration overhead for this feature. JSONB filter via `CoachBrief.evidence['language'].astext` is indexable if we ever want to, and pre-5.2 rows coalesce to 'simple' via `func.coalesce`.
- **Rule-based fallback hard-coerces to 'simple' for any non-'technical' value.** Corrupt or unknown language values must not leak jargon into what's supposed to be plain-English output. This mirrors the endpoint's Literal narrowing.
- **Frameworks cited is language-rewritten in simple mode.** Instead of "Seiler polarized · Banister fitness-fatigue" the footer shows "Grounded in sports science" + plain phrases like "Rest makes you faster". Research names are preserved inside technical mode.
- **Per-browser persistence (localStorage), not per-user.** A user on their phone vs their laptop may have different preferences (quick glance vs deep analytics). Shared device contexts (e.g. a coach's tablet) also benefit from this separation.
- **Cross-tab storage-event sync.** If a user flips the toggle in one tab, other open tabs mirror the change. Small UX polish that's free to add.
- **SyncButton is a mutation + cache invalidation, not a reload.** React Query invalidations let the whole dashboard refresh in place. This is strictly better than `location.reload()` (preserves scroll position, no white flash).
- **TransparencyDrawer stays technical by design.** That drawer IS the "show me the raw nerd data" surface — simplifying it would defeat its purpose. The intro line is the only simple-mode accommodation.
- **Client-side phrase map covers only what the backend can't write.** The coach's generative output (rationale, why_this_workout) is backend-language-aware via SYSTEM_PROMPT_SIMPLE/TECHNICAL. The phrase map handles static UI copy: tooltips, block name hints, CTA labels, category-based workout titles. This keeps the two concerns separate.

## Issues Encountered

- **Existing `test_rationale_cites_data_numbers` test expected TSB/CTL/Banister/Friel in the rule-based rationale.** Default shifted to 'simple', so the test would fail for the wrong reason. Fixed by opting into `language='technical'` in the test fixture — the test still asserts the technical-mode invariant it was designed to, it just stops accidentally asserting "simple mode is the same as technical mode". One-line fix at `tests/test_coach_service.py:134-139`.
- **JSONB filter required `func.coalesce`.** Pre-5.2 rows don't have `evidence.language`, so a naive `CoachBrief.evidence['language'].astext == 'simple'` filter would fail to hit them. Using `coalesce(lang_expr, 'simple')` makes pre-5.2 rows transparent to simple-mode callers, preserving cache warmth after deploy.
- **Unknown language value coerced to 'simple' in `_rule_based_brief`.** Initial implementation branched on `language == 'simple'` with `else` = technical; a corrupt `'klingon'` value fell through to technical, leaking jargon. Switched to `"technical" if snapshot.get("language") == "technical" else "simple"` so unknown = simple (fail-safe for the non-athlete default).

- **Cache strategy scales cleanly.** The `evidence->>'language'` pattern can extend to other coach-output axes in future (e.g., locale, verbosity) without schema churn — each new axis adds a `coalesce(evidence->>axis, default) == requested` filter.
- **Sync button pattern is reusable.** `useForceSync` + `SyncButton` is the template for any future "manually force an external data pull" action (e.g., a recompute-PMC button, a re-ingest-workouts button).

### Known caveats

- **`/coach/why` and `/coach/transparency` endpoints are NOT language-aware server-side.** They return technical evidence strings regardless. The frontend rewrites them for simple-mode display via `simpleEvidenceFor`. If future phases want true server-side language routing for these endpoints, add a `language` query param + thread it through `why_am_i_tired`. For now, client-side rewriting is fine because the evidence is structured (label + text).
- **PMC chart and calendar heatmap retain technical labels (CTL/TSB/TSS).** These are dense analytic panels in fold 4 (collapsed by default) — the same role as TransparencyDrawer's "raw data" view. The plan did not list them for language-mode work; treating them as technical is consistent with TransparencyDrawer's design.
