    ```python
    from typing import Literal
    from app.services.training_periodization import Phase

    Language = Literal["simple", "technical"]
    BlockPosition = Literal["accumulation", "transmutation", "realization", "recovery"]

    def build_weekly_rationale(
        *,
        phase: Phase,
        block_position: BlockPosition,
        block_index_in_meso: int,        # 0..3
        weekly_tss_target: int,
        ctl_now: float,
        ctl_delta_7d: float,             # +3.2 means CTL grew by 3.2 over the past 7 days
        days_to_event: int | None,       # None = maintenance, ≤7 = race week
        target_event_type: str | None,   # 'race' | 'fondo' | 'audax' | 'maintenance' | None
        seiler_z3_pct: float,            # 0.10 = pyramidal-ish, 0.20 = polarized hard, etc.
        language: Language,
    ) -> str:
        """Returns 3-5 sentences describing why this week is structured this way.

        Structure of the paragraph:
          Sentence 1: Phase + block context ("Build phase, week 2 of 4 — sweet-spot accumulation.")
          Sentence 2: Why this volume ("CTL has grown 3.2 over the last week; we're staying inside the 8% ramp.")
          Sentence 3: TID rationale ("80/20 polarized split keeps two hard days and the rest aerobic.")
          Sentence 4 (conditional): Event-anchored if days_to_event is set ("Goal event in 35 days; we're in the build heart.")
          Sentence 5 (conditional): Recovery-week call-out if block_position='recovery' ("This is your recovery week — volume drops 35% so the next block lands.")
        """
    ```

    Implementation:

    Define two parallel dictionaries — `_TECHNICAL_PHASE_COPY` and `_SIMPLE_PHASE_COPY` — keyed by Phase, with template strings that interpolate the dynamic numbers. Examples:

    Technical mode templates:
      - phase='build1' + block='accumulation': "Build phase, week {n} of {meso_len} — sweet-spot accumulation."
      - PMC sentence: "CTL has grown {delta} over 7 days; we're inside Friel's 8% ramp cap."
      - TID: "{z3_pct}% high-intensity / {z1_z2_pct}% aerobic — pyramidal split for build."
      - Event: "{days} days to your A-race; this week is the build heart."
      - Recovery: "Recovery week — TSS drops to {tss}, a {drop_pct}% step-down so the next block lands."

    Simple mode templates (NO CTL/TSS/IF/Z1/Z2/Z3/Coggan/Seiler/polarized/pyramidal/threshold/sweet-spot/VO2):
      - phase='build1' + block='accumulation': "Building week {n} of {meso_len} — steady, controlled hard work."
      - PMC sentence: "Your fitness has climbed nicely this week; we're keeping the increase manageable."
      - TID: "Two hard days, the rest easy — that's how the body actually adapts."
      - Event: "Your goal is {days} days away; this week is the heart of building."
      - Recovery: "This is a back-off week — the workload drops about a third so your body absorbs the work."

    Maintenance mode (target_event_type='maintenance' or no event):
      - Technical: "Maintenance — polarized 80/20, no peak target."
      - Simple: "Staying fit and ready — easy days alternating with two harder ones."

    Race week (days_to_event ≤ 7):
      - Technical: "Race week. Volume reduced ~50%, intensity preserved per Mujika protocol; one opener at race pace."
      - Simple: "Race week — most days are short and easy; one quick wake-up the day before."

    Hard rails (research-driven):
      - simple-mode regex test (in tests): the result MUST NOT contain any of: `\bCTL\b`, `\bTSS\b`, `\bTSB\b`, `\bIF\b`, `\bZ[1-7]\b`, `\bSeiler\b`, `\bMujika\b`, `\bIssurin\b`, `\bFriel\b`, `\bCoggan\b`, `\bsweet[- ]spot\b`, `\bthreshold\b`, `\bVO2\b`, `\bpolarized\b`, `\bpyramidal\b`. (Match the [05.4-01] simple-mode jargon discipline.)
      - technical-mode is allowed all of the above.
      - Sentences are joined with single space + period; result is a single paragraph (no newlines).
      - 3-5 sentences total — count `.` excluding ellipses; assert in tests.
      - Never punish rest: recovery-week copy must be POSITIVE (no "you missed", "behind schedule" copy). [05-01] hard rail extends.

    Implementation hint: Build the rationale as a list of `str | None` from helpers (`_phase_block_sentence`, `_pmc_sentence`, `_tid_sentence`, `_event_sentence_or_none`, `_recovery_sentence_or_none`), filter out None, join. Keeps each sentence individually testable.
