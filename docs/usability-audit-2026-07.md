# Usability Audit — July 20, 2026

*Four evaluators (personas Lena/beginner, Marc/racer, Sofia/casual + UX-heuristics expert) drove the live app sequentially (mobile-first), logging 85 issues; an expert designer deduped them into 16 prioritized solutions. Raw JSON preserved below.*

## Cross-cutting themes

- No single source of truth: every surface computes its own FTP/CP, TSB, streaks, weekly targets, countdowns and ride counts, so the app contradicts itself at every seam — and one corrupt best-effort (359 W) poisons the CP model, race pacing and goals downstream.
- The coach speaks with four voices: Today, Recovery, Load-Form and Chat each issue an independent instruction for the same day (rest / go hard / quality session / no second session), violating the product's own 'one readiness story' principle.
- Broken time and attribution: a day-boundary bug plus sport-blind grading makes the AI narrate a false reality — yesterday's gym session celebrated and simultaneously graded as today's failed bike ride, with stale 'you skipped' notes — fatal for an adaptive-coach premise.
- Guilt by default: red shortfall math, an ACWR injury gauge, 800-TSS challenges, auto-duels you're losing on Monday and daily streaks all contradict the stated no-guilt identity and the explicit 'kein XP, keine Streaks' promise.
- Unfinished chrome undermines the persona: mixed EN/DE mid-card, sub-AA 9–10px type, hover-only affordances on a phone-first product, an inert 'simple mode' and false tab states make a warm coach feel machine-generated.

## Designer solutions

### [P0] One canonical threshold. Build a single `powerThreshold` selector every surface must read; ban local CP/FTP math in components. Pipeline: (1) sanitize best-efforts — reject any rolling-window peak exceeding the all-time PR for that duration by >5% (kills the 359 W 20-min artifact) and require 2+ corroborating efforts before a value enters the CP fit; (2) fit CP on sanitized data; (3) if CP disagrees with detected FTP by >10%, suppress CP/W′ display and fall back to detected FTP. Display exactly one number app-wide, labeled EN 'FTP (estimated) 240 W' / DE 'FTP (geschätzt) 240 W'; CP/W′ live only in a collapsed 'Model details / Modelldetails' row on /power-profile once validated. Rewire dependents: /climbs pacing, /season race pacing (88–94% of 240 → 211–226 W climbs), zone tables, workout watt targets, and collapse the two FTP forecasts (Train + Progress) into one projection function — when its own confidence is <30%, show a range not a point (EN 'Trending toward 235–250 W by race day' / DE 'Richtung Renntag: 235–250 W möglich') and drop the '≈13 min faster' race-time claim. Season goal card: delete the auto 350 W target; empty state EN 'No FTP target set — choose one (suggested: 252 W, +5%)' / DE 'Kein FTP-Ziel gesetzt — Ziel wählen (Vorschlag: 252 W, +5 %)'.
*Rationale:* Four blocker/major reports across all personas trace to one corrupt best-effort feeding an unguarded CP model that then propagates into physically impossible race pacing and a demoralizing 350 W goal. One producer plus outlier rejection fixes the whole chain at once and restores the 'kennt deine echten Daten' promise.
*Solves:* /power-profile+YOUR ENGINE card (CP 363 / eFTP 366), /climbs+Pacing Plan 'Based on your CP · 243 W', /season+Race Day Plan pacing card (319–341 W climbs), /season+Season Goals — Target FTP 240 / 350 W, ?tab=plan+PROJECTION card (223→225 vs 'today ~240'), /progress/bike+FTP Forecast ('Projected 249 W · 3% confidence' vs History 'confidence: high')

### [P0] Fix the clock and the grading gate. (1) Day boundary: one shared `isToday()` util using the athlete's local timezone feeds hero, weekly TSS, Recovery strain, duel and Coach briefing — yesterday's 10:21 session can never be 'heute'. (2) Grading gate in the Session Review: a completed activity is graded against a planned session only when calendar day AND sport family match; otherwise render an ungraded 'logged' card — no grade, no % chips, no dashes-with-a-B. Cross-sport credit: EN 'Yesterday: 58 min strength — 1 of 2 strength sessions done.' / DE 'Gestern: 58 Min Krafttraining — 1 von 2 Kraft-Einheiten geschafft.' (3) Delete the machine sentence 'Nächstes Mal ziel auf eine engere Übereinstimmung…' everywhere; same-sport shortfall copy becomes EN 'Shorter than planned — fine. The week absorbs it.' / DE 'Kürzer als geplant — völlig okay. Die Woche fängt das auf.' and the card renders once (Today only; Plan links to it). (4) Adaptive coach notes (Plan HINWEISE) validate against the calendar before render — they may only reference sessions whose scheduled time is in the past; stale notes are dropped, never shown.
*Rationale:* Wrong day + wrong sport + a false 'you skipped' note means the AI narrates a past that didn't happen — disqualifying for an adaptive coach and the root of the absurd 'Ruhetag + Einheit erledigt' screen. Gating the grade also removes the worst guilt moment (−78% for doing the strength work the plan itself asked for).
*Solves:* ?tab=today+Hero 'Einheit erledigt / 58 min heute geschafft', ?tab=today+Session Review (yesterday's Krafttraining graded as today's Z2 ride), /coach+Briefing 'You already got a ride in today', ?tab=today+'Einheit abgeschlossen' stat row (— dashes + grade B), ?tab=today/?tab=plan+Coach advice line 'Nächstes Mal ziel auf…' (machine German, shown twice), ?tab=plan+Coach NOTES stale 'You skipped Tuesday's ride'

### [P0] One Daily Decision. Compute a single `dailyDecision` object once per day — {verdict: rest | easy | quality | hard, reason, cta} — from plan + readiness + rolling 48h/7d load + TSB, and make Today hero, Recovery, Load-Form and Coach all render it subordinately; no surface may issue its own instruction. On a planned rest day with green recovery, Recovery reframes instead of contradicting: EN 'Well recovered — and today is a planned rest day. Bank it for tomorrow's quality session.' / DE 'Gut erholt — und heute ist Ruhetag geplant. Nimm die Frische mit in die morgige Einheit.' Load-Form hides 'Einheit öffnen' on rest days and shows EN 'Green light for tomorrow' / DE 'Grünes Licht für morgen'. The Recovery load target is expressed in the plan's unit (TSS, or 'Belastung' in simple mode), rendered only on training days: EN 'Load target today: ~15 TSS (easy day)' / DE 'Belastungsziel heute: ~15 TSS (lockerer Tag)'.
*Rationale:* Every persona hit this: whichever tab you open decides your training. 'One readiness story' is a stated design principle — it needs an architectural enforcement point, not better copy on four independent engines.
*Solves:* cross-surface+Daily recommendation (Today 'Ruhetag' vs Recovery 'höhere Belastung' vs Load-Form 'Grünes Licht — belaste hart' vs Coach 'keine zweite Einheit'), ?tab=recovery+'Belastungsziel heute 15.1' card (third load unit, on a rest day), /load-form+'Grünes Licht — belaste hart · Einheit öffnen' CTA, ?tab=recovery+'Erholt — trainiere mit Absicht' push on planned Ruhetag

### [P0] Make the race-day forecast simulate the plan or say nothing. The CTL projection must integrate the known 20-week planned TSS ramp (simulate CTL/ATL forward through it, including the taper, which also yields a sane race-day TSB instead of −16). Add render guards: a projection of 0 while an active plan exists is invalid → show the honest-dash state: EN 'Forecast coming — we need 2–3 more training weeks to project race day.' / DE 'Prognose folgt — nach 2–3 Trainingswochen können wir den Renntag hochrechnen.' All derived output ('add ~25 TSS/week', '~296 TSS/Wo. nötig', the 0% ring, the 'HINTER DEM ZIEL' badge) is suppressed in the dash state; the badge appears only when a valid projection misses target by >10%.
*Rationale:* Three personas called this the single most 'you are failing' screen, built on an impossible number and generating actionable advice from a null. The plan data needed for a correct simulation already exists — no new sources required.
*Solves:* /season+'Prognose Renntag' card (CTL 33 → 0, 0% ring, 'HINTER DEM ZIEL', '~296 TSS/Wo. nötig', 'Form am Renntag −16')

### [P0] Shared metrics layer: every small number gets exactly one producer. `tsb()` rounds once (33 − 26 = +7 everywhere); `weeklyPlannedTSS()` includes the strength sessions as visible line items (week list gains a row 'Kraft ×2 · 10 TSS' so header and list reconcile) and is the only source for 'target' on Plan, Load-Form, Recap and Season; `daysToEvent()` is one ceil-in-local-TZ util (138 everywhere); `rideCounts()` is one query — if a caption filters, it must say so or it's a bug; `loadBySport()` computes hrTSS for runs from HR when power is absent (a 45-min HR-117 run is never 0 TSS, so CTL/ATL stop silently undercounting multi-sport load); the '+69% rising' trajectory chip is removed until it reads the same CTL series as the −4/wk tile. Streak unification is handled by the P1 streak rework. Add a CI snapshot test that renders every surface against one fixture athlete and diffs each displayed metric value across surfaces.
*Rationale:* Individually minor, together these teach attentive users that no number can be trusted at face value — corrosive for a data coach. A selector layer plus a cross-surface consistency test prevents regression permanently, and the run-TSS fix corrects genuinely wrong form math.
*Solves:* ?tab=today vs /load-form+Form/TSB +1 vs +7 (same CTL 33 / ATL 26), ?tab=today vs ?tab=history vs ?tab=social+streak 4 vs 1 vs 0/7, /load-form vs ?tab=plan vs /recap vs /season+weekly TSS target — / 271 / 294 / 285, ?tab=plan+week header 294 vs listed sessions 284, cross-surface+days-to-event 138 vs 139, /power-profile vs /achievements vs /routes+ride counts 72 / 58 / 54

### [P1] Full localization pipeline. (1) AI-generated coach copy is produced in the UI locale (locale passed to the generator); if a cached insight's locale ≠ UI locale, regenerate or fall back to a translated template — never render English inside a German card.
