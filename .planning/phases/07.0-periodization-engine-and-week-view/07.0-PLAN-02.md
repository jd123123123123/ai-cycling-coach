<objective>
Build the deterministic mesocycle generator: take an athlete's target event + current state, emit a 4-week plan with daily PlannedWorkout drafts that respect Friel macrocycle phase, Issurin 3:1 block structure (3 build weeks + 1 recovery), and Seiler weekly TID.

Purpose: The core periodization engine. Phase 5.1 already gives us session_type_for_today / pick_template / phase detection for the SINGLE-DAY case; this plan extends that into a forward 4-week mesocycle so (a) Plan 04's /weeks/current endpoint has structured data to serve, (b) Plan 03's weekly rationale generator has a meso-block context to explain, (c) Phase 7.1's daily readiness adapter has a written-down plan to swap against without losing weekly intent.

Output: New `mesocycle_plans` table, ORM model, generator service with full test coverage.
</objective>

    ```python
    async def generate_mesocycle(
        db: AsyncSession,
        user_id: int,
        plan_start_date: date | None = None,  # defaults to next Monday
    ) -> MesocyclePlan:
        """Generate or return existing MesocyclePlan for (user_id, plan_start_date).
        Idempotent: if a plan exists for that anchor, return it unchanged.
        Otherwise: create plan + 28 PlannedWorkout drafts (4 weeks × 7 days).
    ```

    ```python
    def issurin_block_for_week(week_index: int, total_weeks: int = 4) -> Literal["accumulation", "transmutation", "realization", "recovery"]:
        """Issurin 3:1 — weeks 0..2 = build (accumulation/transmutation/realization),
        week 3 = recovery (TSS reduced ~30-40%)."""

    def weekly_tss_target(
        ctl: float,
        phase: Phase,
        block_position: Literal["accumulation", "transmutation", "realization", "recovery"],
    ) -> int:
        """CTL × 7 × ramp_factor; ramp 1.05 / 1.10 / 1.15 across build weeks then 0.65 for recovery.
        Hard cap: ramp_factor ≤ 1.08 absolute (Friel 8% rule); for high-CTL athletes ramp shrinks."""

    def build_week_drafts(
        athlete: AthleteProfile,
        week_start: date,
        phase: Phase,
        weekly_tss_target: int,
        block_position: Literal["accumulation", "transmutation", "realization", "recovery"],
        ftp_w: int,
    ) -> list[PlannedWorkoutDraft]:
        """Pick 7 templates respecting Seiler distribution + hard-session count for the phase.
        Monday=rest, Wednesday=key workout day for build/peak (per existing 5.1 cascade decision in coach_service).
        Returns drafts (NOT yet persisted) — caller persists in transaction with the parent MesocyclePlan."""
    ```

    Concrete rules (lock these — no LLM, no fuzziness):
      - Phase mapping: call `detect_training_phase(target_event_date, current_ctl_7d)`. If target_event_type=='maintenance' OR target_event_date is None: phase='maintenance'.
      - Issurin 3:1: weeks 0,1,2 increase TSS by ~5/10/15% over current CTL×7 baseline. Week 3 drops to ~65% (recovery week).
      - Seiler TID per phase (REUSE the dictionary from `training_periodization._target_distribution_for_phase`; do NOT duplicate; import it):
        - base1: 90/10 (Z1+Z2 / Z3+) — 0 hard sessions
        - base2: 85/15 — 1 threshold per week max
        - build1: 80/20 — 2 hard (sweet-spot + threshold)
        - build2: 75/25 — 2-3 hard (sweet-spot + VO2 + threshold by Issurin block)
        - peak: 80/20 — race-specific
        - taper: 85/15 — see Phase 7.2 for Mujika; for 7.0 just respect the phase mapping
        - race: 100/0 — full rest + opener only
        - maintenance: 80/20 polarized indefinitely (Seiler)
      - Day-of-week template: reuse `session_type_for_today` for each of the 7 days. For days not "today", call it with synthetic snapshot: `weekly_progress` reflects the in-progress week being built (cumulative TSS so far), `intensity_ceiling=None` (no readiness signals applied at generation time — that's Phase 7.1's job).
      - Hard rail: every block in every PlannedWorkout draft has `power_target_pct_ftp` (a fraction or None for warm-up/cool-down), NEVER absolute watts. Materialisation happens at request time.
      - Multi-sport interference (research §6): if athlete.primary_sport='running', hard sessions are running-flavoured templates (when 7.2 ships them; for 7.0 fall back to cycling templates and tag sport='cycling' — primary-sport flow lives in the template library, not the generator). Strength sessions: schedule on Mon (or Thu) when phase is build1/build2 AND athlete has gym in secondary_sports.
      - Idempotency: generator first SELECTs MesocyclePlan WHERE user_id AND plan_start_date. If exists, returns it without touching PlannedWorkout. If not, INSERTs MesocyclePlan THEN bulk-inserts PlannedWorkout rows in the same transaction.
      - PlannedWorkout draft fields: user_id, date, sport (from athlete.primary_sport, default 'cycling'), title (template.title), duration_seconds_target (template.base_duration_minutes × 60), interval_structure (`{"intervals": [...]}` from template.blocks), template_id (the registry key), blocks_source='ai_prescribed'. DO NOT set indoor.
      - Conflict-on-insert behaviour: if a PlannedWorkout already exists for (user_id, date), SKIP (do not overwrite — 06.x modification flow may have user-modified rows). Document this in the docstring.
