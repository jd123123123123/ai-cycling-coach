# Phase 5.1: Precision Prescription + iPhone Hierarchy Summary

**Reshapes Phase 5's vague 4-option coach brief into ONE precisely-prescribed workout grounded in the athlete's FTP, CTL, TSB, HRV, and a Friel-phase selector; redesigns the dashboard for iPhone-level cognitive deload (one call-to-action per fold, progressive disclosure).**

## What changed

### Backend (5 commits)

1. **`workout_templates.py`** — 12 parametric templates (rest_day, recovery_30, z2_endurance_60/90/120/180, tempo_3x10, sweet_spot_2x20, threshold_2x15, over_under_3x5, vo2_5x4, vo2_micro_30x30). Each block carries `target_pct_ftp` + zone + RPE; watts are computed at request time via `parametrize_template(template, ftp)` with zone-aware tolerance bands (±5% on VO2, ±10% on Z1 recovery).

2. **`training_periodization.py`** — `detect_training_phase` maps goal_date + CTL to a Friel phase (offseason → base1/2 → build1/2 → peak → taper → race). `weekly_intensity_quota` returns phase-weighted Seiler split. `session_type_for_today` is a first-match-wins cascade: intensity_ceiling → phase → day-of-week → weekly_progress. `pick_template` resolves category + available minutes + FTP to a concrete template.

3. **`coach_service.py` reshape** — `build_snapshot` now detects phase, computes weekly_quota, runs session_type_for_today, and pre-picks+parametrises the template the LLM sees. New `resolve_and_prescribe(snapshot, llm_payload)` is the server-side watts authority: validates template_id, enforces rails ceiling (downgrades above-ceiling templates), rewrites watts from FTP, synthesises missing alternates. `_rule_based_brief` rebuilt on templates so the fallback produces a complete PrescribedWorkout.

4. **`coach_prompt.py` reshape** — SYSTEM_PROMPT moves from "4-option coach" to "prescriptive coach"; explicit rule that the LLM rubber-stamps the picker's template and can only substitute to an adjacent template for a signal-based reason. BRIEF_TOOL schema swaps `options[]` for `prescribed_workout` + `alternates[]`.

5. **Alembic `a7b8c9d0e1f2`** — adds `prescribed_workout JSONB` + `alternates JSONB` columns to `coach_briefs`, relaxes `options` to NULLABLE. Pydantic `BriefRead` updated; legacy `options[]` kept optional for backward compat on old rows.

**`test_periodization.py` (28 tests)** — phase boundaries (16w/12w/6w/3w/7d); weekly_quota phase splits; session_type_for_today respects intensity_ceiling; pick_template FTP gate (no VO2 <180W) + minutes fit.

**`test_coach_service.py` (22 tests, rewritten)** — LLM's absurd watts always rewritten from FTP; unknown template_id falls back to picker; moderate ceiling downgrades VO2 → sweet_spot with inline note; rest ceiling → rest_day; alternates always exactly 2 labels (missing ones synthesised); 3h VO2 from rogue LLM clamped to 65 min.

## Deviations from plan

### Auto-fixed (Rule 1 / Rule 2)

**1. [Rule 1 — Cognitive-deload violation] ReadinessHero's internal KpiStrip was duplicating information**

- **Found during:** Task 10 polish
- **Issue:** The plan called for "ReadinessHero with CoachBrief" in fold 1 and "KpiStripCompact" in fold 2. But ReadinessHero already renders a 5-card KPI grid internally. Keeping both means the user sees HRV/body-battery/sleep twice on one page — the opposite of the user's iPhone bar ("everything you see brings immense value and cognitive deload").
- **Fix:** Stripped the in-hero KpiStrip. Fold 1 hero now shows only the readiness dial + verdict + CoachBrief + PrescribedWorkoutCard. Fold 2 owns the raw KPIs.
- **Files:** `frontend/src/components/dashboard/ReadinessHero.tsx`
- **Commit:** 86cdda7

**2. [Rule 2 — Missing critical] LLM would otherwise hallucinate watts**

- **Found during:** Task 3
- **Issue:** The plan describes `resolve_and_prescribe` but a strict implementation that only validates the LLM's response shape still lets hallucinated watts through. A malicious or confused LLM could return `target_watts_low: 999, target_watts_high: 9999` and those numbers would flow to the athlete.
- **Fix:** `resolve_and_prescribe` now unconditionally rewrites the blocks by re-parametrising the template from the athlete's FTP. The LLM's block watts are ignored — only `template_id` + `duration_minutes hint` + `why_this_workout` are read back. Two-layer defense: `parametrize_template` also clamps `duration_scale` to [0.7, 1.15] internally.
- **Files:** `backend/app/services/coach_service.py`, `backend/app/services/workout_templates.py`
- **Commit:** d5525e8

**3. [Rule 2 — Missing critical] Missing alternates were rejection-worthy**

- **Found during:** Task 3
- **Issue:** The plan's alternates schema requires exactly 2 items (less_time + recover). A strict reading says missing alternates should fail the response. That would take down the entire brief for a minor LLM lapse.
- **Fix:** `resolve_and_prescribe` synthesises missing alternates with sensible defaults (less_time → z2_endurance_60 or recovery_30, recover → recovery_30). Also deduplicates by label and replaces invalid template_ids. The UI always has 2 valid alternates to render.
- **Files:** `backend/app/services/coach_service.py`
- **Commit:** d5525e8

**4. [Rule 3 — Blocking] `RecentActivities` didn't accept a `limit` prop**

- **Found during:** Task 8
- **Issue:** Plan says fold 3 should show "last 5 only, not 10"; `RecentActivities` hardcoded `.slice(0, 10)`.
- **Fix:** Added `limit?: number` prop defaulting to 10. Dashboard passes limit=5.
- **Files:** `frontend/src/components/dashboard/RecentActivities.tsx`
- **Commit:** 9f01774

- **Post-ride compliance scoring** — not in scope here. The prescribed_workout persists in coach_briefs; a future plan can compare against the actual Activity record to produce a "how close was the session to prescription" score.
- **Send-to-Garmin workout export** — deferred to a later plan. The blocks already carry everything Garmin's .fit workout format needs (seconds + watts_low + watts_high + zone).
