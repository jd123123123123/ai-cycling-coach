    Create `frontend/src/utils/format.ts` exporting:

    ```ts
    /**
     * formatSigned(n, digits=0) — explicit sign, typographic minus (U+2212), tabular-friendly.
     *  formatSigned(0, 0)  -> "0"        (no sign on zero)
     *  formatSigned(18, 0) -> "+18"
     *  formatSigned(-3.4, 1) -> "−3.4"   (NOTE: U+2212, not hyphen-minus)
     */
    export function formatSigned(n: number, digits = 0): string;

    /**
     * formatHours(seconds) — Whoop-style: ≤9.9h shows one decimal, ≥10h shows integer.
     *  formatHours(2520)  -> "0.7h"
     *  formatHours(36000) -> "10h"
     *  formatHours(null)  -> "—"
     */
    export function formatHours(seconds: number | null | undefined): string;

    /**
     * formatDelta(curr, prev) — pct change w/ sign and "%". Returns null on insufficient data.
     *  formatDelta(110, 100) -> "+10%"
     *  formatDelta(90, 100)  -> "−10%"
     *  formatDelta(0, 0)     -> null
     */
    export function formatDelta(curr: number | null | undefined, prev: number | null | undefined): string | null;
    ```

    Implementation rules:
    - `formatSigned`: use `n === 0 ? '0' : (n > 0 ? '+' + n.toFixed(digits) : '−' + Math.abs(n).toFixed(digits))`. The minus is the Unicode character U+2212, not the ASCII hyphen-minus. This is non-negotiable per research doc §2.4.4.
    - `formatHours`: handle null/undefined/NaN by returning `"—"` (em-dash). Round to one decimal up to 9.95s, integer at ≥10. Lift the existing implementation in `WeekStrip.formatHours` if present; otherwise write fresh.
    - `formatDelta`: returns null if either input is null/undefined/NaN/0. Computes `(curr - prev) / prev * 100`, rounds to integer, prefixes via `formatSigned`. Suffix with `'%'`.

    Create `frontend/src/utils/delta.ts` exporting:

    ```ts
    export type DeltaTone = 'muted' | 'forest-2' | 'forest' | 'amber' | 'alert';

    /**
     * toneFromPct — polarized-accent thresholds from research §2.4.3.
     *  |Δ| < 3            -> 'muted'
     *  3..10 in good dir  -> 'forest-2'
     *  >10  in good dir   -> 'forest'
     *  3..10 in bad dir   -> 'amber'
     *  >10  in bad dir    -> 'alert'
     *
     * direction: 'good' means positive=good (e.g. HRV up); 'bad' means positive=bad (e.g. RHR up).
     */
    export function toneFromPct(pctChange: number | null | undefined, direction: 'good' | 'bad'): DeltaTone;

    /**
     * tokenForTone — returns the CSS var() string for a tone.
     *  tokenForTone('forest-2') -> 'var(--color-forest-2)'
     *  tokenForTone('muted')    -> 'var(--color-muted)'
     */
    export function tokenForTone(tone: DeltaTone): string;
    ```

    Implementation: `toneFromPct` returns 'muted' on null/undefined/NaN. The `direction='good'` branch is the literal pattern in `KpiStripCompact.toneFromPct` today — lift it verbatim if present, otherwise implement fresh against the spec. `tokenForTone` is a 5-case switch returning literal strings (not template literals — keep CSS var names easy to grep).
