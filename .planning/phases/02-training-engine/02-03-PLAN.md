  <action>
    Create backend/app/services/pmc_service.py:
    - get_daily_tss_by_sport(db: AsyncSession, user_id: int, days: int = 90) -> list[dict]
      - Query activities table: GROUP BY date (via time_bucket or date_trunc), sport
      - Use raw SQL with sqlalchemy.text() for the time_bucket query
      - Use f-string for interval days (server-side constant, not user input)
      - Returns list of {"day": date, "sport": str, "daily_tss": float}
    - compute_user_pmc(db: AsyncSession, user_id: int, days: int = 90) -> dict
      - Call get_daily_tss_by_sport to get raw data
      - Separate TSS by sport (cycling, running, gym)
      - For each sport: build list of {"date": date, "tss": float}, call compute_pmc_series()
      - For total: sum all sport TSS per day, call compute_pmc_series()
      - Return {"total": [...PMCEntries], "cycling": [...], "running": [...], "gym": [...]}
      - Gap-fill in Python (not time_bucket_gapfill — per research, gapfill with per-sport GROUP BY is unreliable)
    - get_zones(profile: AthleteProfile) -> dict
      - If profile.ftp_watts: call coggan_power_zones(profile.ftp_watts)
      - If profile.running_threshold_pace_ms: call seiler_3_zones_running(profile.running_threshold_pace_ms)
      - Return dict with power_zones and/or pace_zones (only if thresholds are set)

    Create backend/app/api/training_load.py:
    - GET /training-load/pmc — query param: days (int, default 90, max 365). Returns PMCResponse with per-sport + total entries.
    - GET /training-load/zones — returns current power zones and pace zones based on athlete profile. Returns 200 with available zones (may be partial if only cycling or only running thresholds set).

    Both endpoints use get_current_active_user + get_db_for_user for RLS.

    Register training_load router in backend/app/main.py with prefix="/training-load" and tag="training-load".
