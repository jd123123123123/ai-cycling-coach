## Decisions Made

- **ATL amber is allowed**: `var(--color-amber)` for ATL sparkline stroke is legitimate — ATL = "fatigue" has caution semantics; research §3.4 explicitly permits this. Only 1 amber usage in PMCChart.
- **Sparkline as children**: `SummaryStat` accepts a `children` slot; callers pass `<Sparkline>` directly. This satisfies the `grep -c '<Sparkline'` ≥ 3 verify check and is cleaner than prop-drilling data + stroke.
- **28-day data wired, not deferred**: The plan mandated real data for the week-vs-4w line. `useActivitiesRange` accepts any date range — extending to 28 days required one additional hook call with `subDays(weekStart, 21)`. This is single-line-trivial per the plan's own escape criteria, so no blocker, no deferral.
- **Polarized 14-day sparkline DEFERRED**: `useActivitiesRange` returns a flat list of `ActivityRead` items. Computing `lowPctSeries` (one low-zone-pct value per calendar day) requires iterating and bucketing by date into 14 slots. This is not a query parameter change — it's local computation that is feasible but non-trivial given the activity list shape. The must_haves explicitly list only the 3-row table + zone tokens; sparkline was best-effort. No placeholder rendered. Documented here.
