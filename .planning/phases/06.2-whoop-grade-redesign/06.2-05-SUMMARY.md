## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] KpiCell.tone type changed from local DeltaTone enum to CSS string**

- **Found during:** Task 1 (KpiStripCompact migration)
- **Issue:** Local `DeltaTone` type ('good'/'warn'/'bad'/'neutral') was incompatible with `tokenForTone()` return type (CSS var() string). Keeping both systems would require a bridge layer with duplicate logic.
- **Fix:** Changed `KpiCell.tone` to `string` (CSS var()); updated `KpiCellView` to use `cell.tone` directly as color; updated icon selection to use `cell.deltaPct + cell.higherIsBetter` instead of tone enum.
- **Files modified:** KpiStripCompact.tsx
- **Verification:** tsc --noEmit clean; visual parity preserved (same color thresholds, same icon behavior)
- **Committed in:** 5bfc796

**2. [Rule 1 - Bug] TSB tone mapping kept bespoke (non-monotonic good/bad logic)**

- **Found during:** Task 1 (cells array migration)
- **Issue:** TSB has a non-monotonic good/bad relationship (very positive TSB = over-rested/detrained = amber warning). `toneFromPctShared('good')` would incorrectly mark high TSB as 'forest'. 
- **Fix:** TSB tone uses direct CSS token mapping: `tsb < -20 → alert`, `< -10 → amber`, `> 20 → amber`, else `forest-2`. Uses `tokenForTone`'s token strings directly without calling `toneFromPctShared`.
- **Files modified:** KpiStripCompact.tsx
- **Committed in:** 5bfc796
