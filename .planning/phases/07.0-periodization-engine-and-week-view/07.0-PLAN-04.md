    Endpoint:
    ```python
    @router.get("/current", response_model=WeekResponse)
    async def get_current_week(
        language: Language = Query("simple"),
        db: AsyncSession = Depends(get_db),
        current_user: User = Depends(get_current_user),
    ) -> WeekResponse:
        """Return today + next 6 days as a planned week with rationale.
        Generates a mesocycle if the athlete doesn't have one for the current week.
        """
    ```

    Logic:
      1. Compute `today = local-date()` (use the same `_today_local` helper coach_service uses; import it).
      2. Compute `week_start = today - timedelta(days=today.weekday())` (Monday) — the meso anchor.
      3. Call `await generate_mesocycle(db, current_user.id, plan_start_date=week_start)` — idempotent; creates if missing, returns existing otherwise.
      4. Load AthleteProfile for current_user (need ftp_watts + target_event_date + target_event_type).
      5. Compute `current_ctl_7d` and `ctl_delta_7d` via existing `pmc_service.compute_user_pmc` — match the call shape used in coach_service.
      6. Compute `days_to_event = (target_event_date - today).days if target_event_date else None`.
      7. SELECT 7 PlannedWorkout rows for current_user.id WHERE date >= today AND date <= today+6. Order by date.
      8. For each PW, compose DayPlan: project intervals from interval_structure JSON; compute target_tss from template registry (`templates.TEMPLATES[template_id].base_tss * duration_scale`); compute category by mapping template_id to its category (template.category attribute); compute one-sentence per-day rationale via a small helper `_per_day_rationale(category, day_index, phase, language)` — keep it deterministic, ~20 lines, no LLM. (Sample copy: simple "Easy spin to recover" / technical "Recovery 30 — flush the legs after Tuesday's threshold".)
      9. Compute MesoBlockContext: derive `block_index_in_meso` from `(today.toordinal() - meso.plan_start_date.toordinal()) // 7` clamped [0,3]; derive `block_position` via `mesocycle_generator.issurin_block_for_week(block_index_in_meso)`; pull `weekly_tss_target` from `meso.weekly_tss_targets[block_index_in_meso]`.
      10. Compute `seiler_z3_pct` from `meso.seiler_distribution["z3_pct"]`.
      11. Call `build_weekly_rationale(...)` with all the gathered context + language → preface.
      12. Return WeekResponse.

    Edge cases:
      - Athlete has no FTP: return 409 with `{"detail": "Set your FTP before generating a plan", "code": "ftp_required"}`. Do NOT 500.
      - Athlete has no AthleteProfile row: return 409 with `{"detail": "Complete your profile setup first", "code": "profile_required"}`.
      - Maintenance mode (no event date / type='maintenance'): proceed normally; preface uses maintenance copy from Plan 03.

    ```typescript
    import { apiClient } from './client'

    export interface IntervalBlockOut {
      duration_seconds: number
      power_target_pct_ftp: number | null
      zone: number  // 1..7
    }

    export interface DayPlan {
      date: string  // ISO YYYY-MM-DD
      sport: string
      title: string
      template_id: string | null
      duration_seconds_target: number | null
      target_tss: number | null
      category: 'rest'|'recovery'|'endurance'|'tempo'|'sweet_spot'|'threshold'|'vo2'
      intervals: IntervalBlockOut[]
      rationale: string
      is_today: boolean
    }

    export interface MesoBlockContext {
      phase: string
      block_position: 'accumulation'|'transmutation'|'realization'|'recovery'
      block_index_in_meso: number
      weekly_tss_target: number
      days_to_event: number | null
      target_event_type: string | null
    }

    export interface WeekResponse {
      week_start: string
      week_end: string
      language: 'simple' | 'technical'
      preface: string
      meso_block: MesoBlockContext
      days: DayPlan[]
    }

    export async function fetchCurrentWeek(language: 'simple' | 'technical'): Promise<WeekResponse> {
      const res = await apiClient.get<WeekResponse>('/weeks/current', { params: { language } })
      return res.data
    }
    ```

    Create `frontend/src/hooks/useCurrentWeek.ts`. Pattern: clone the structure of `useCoachBrief.ts` (read it first). Key bits:
    ```typescript
    import { useQuery } from '@tanstack/react-query'
    import { fetchCurrentWeek, type WeekResponse } from '../api/weeks'
    import { useLanguage } from './useLanguage'

    export const WEEK_CURRENT_KEY_ROOT = ['weeks', 'current'] as const

    export function useCurrentWeek() {
      const { language } = useLanguage()
      return useQuery<WeekResponse>({
        queryKey: [...WEEK_CURRENT_KEY_ROOT, language],
        queryFn: () => fetchCurrentWeek(language),
        staleTime: 30 * 60 * 1000,    // 30 min — research §3 "one adaptation per day max"
        refetchOnWindowFocus: true,    // morning re-open should pull a fresh plan
        retry: (count, error) => {
          // mirror App-level retry:false on 401/403/404/409 (per [04-01])
          const status = (error as any)?.response?.status
          if ([401, 403, 404, 409].includes(status)) return false
          return count < 2
        },
      })
    }
    ```

    Hard rails:
      - Match the [05.2-01] cache-key pattern: language is part of the key, so toggling language fires a fresh fetch.
      - 409 errors short-circuit retry — UI in Plan 05 will detect 409 and render the "set FTP first" CTA.
